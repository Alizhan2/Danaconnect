# DanaConnect Admin

Отдельное приложение для администраторов. Локальный адрес: `http://127.0.0.1:3001`.

## Запуск

1. Запустите API платформы и выполните необходимые миграции.
2. Скопируйте `.env.example` в `.env.local` и настройте `API_BASE_URL` и `NEXT_PUBLIC_WEB_URL`.
3. Добавьте адрес админ-приложения в доверенные Origin backend. Локально это `http://127.0.0.1:3001`; для облака нужен фактический HTTPS-адрес.
4. В папке `apps/admin` выполните `npm ci`, затем `npm run dev`.

Для локального preview готовой сборки: `npm run build`, затем `npm run start`. Общий launcher `scripts/serve-next.mjs` копирует `.next/static` и существующий `public` в standalone runtime и запускает `server.js` на `127.0.0.1:3001`, передавая сигналы остановки. Он не устанавливает зависимости и не собирает приложение. Dockerfile отдельно упаковывает те же ресурсы и слушает контейнерную сеть; локальный launcher предназначен для preview.

## Размещение на одном домене

`ADMIN_BASE_PATH=/admin` нужно задать **до сборки**. Тогда маршруты приложения и его ресурсы получают префикс `/admin`. Локальный запуск использует пустой префикс. Изменение префикса требует новой сборки.

Прокси облачной среды направляет `/admin/*` в это приложение, `/api/*` в FastAPI, остальные маршруты — в пользовательское приложение. Запросы клиента идут в общий `/api/v1` с cookie и `Accept-Language`. Переписывание API настроено с `basePath: false`, поэтому префикс админ-приложения не меняет адрес API. `API_BASE_URL` и публичные адреса нужно задавать при сборке.

## Авторизация

Администратор должен быть назначен оператором платформы. Получить административную роль при обычной регистрации нельзя. После одноразового email-кода приложение обрабатывает ответ MFA challenge и запрашивает код TOTP. Сеанс выдаётся сервером только после завершения проверки. Настройка MFA выполняется оператором через backend CLI; интерфейс не создаёт секреты аутентификатора и не сохраняет их в браузере.

В локальной демонстрации API может вернуть `debug_code`; интерфейс показывает его только при наличии этого поля. Production не должен возвращать такие коды. Все разделы проверяют `/admin/me`, а каждое административное действие независимо проверяет роль и MFA на сервере.

## Реализованные разделы

- Обзор и очереди обработки.
- Участники: поиск, роль, приостановка и восстановление с обязательным пояснением; отображается фактически возвращённый статус.
- Модерация анкет и проектов.
- Создание и редактирование направлений.
- Документы: создание, новая неизменяемая версия, тексты RU/KZ/EN, история и хеш, название и активность.
- Обращения поддержки и история административных действий.
- Публичные комментарии: очередь с пагинацией, намеренный выбор публикации/скрытия и обязательная причина; приватные комментарии не раскрываются.
- Учебные материалы и награды: отдельный раздел управления.
- Участие и встречи: просмотр, пауза/возобновление, досрочное завершение и отмена будущей встречи с причиной.
- Опциональная проверка AI-предложений: запрашивается только после согласия участника, требует настроенного провайдера и сохраняет отдельное решение человека; анкету автоматически не одобряет.
- Проверка результатов, отзывы, CSV и аналитика реальной текущей базы с маркировкой демонстрационных данных.
- Запросы выгрузки, деактивации и удаления данных. Удаление нельзя отметить выполненным через форму; нужна отдельная процедура очистки и проверки сроков хранения. Выполнение деактивации использует backend для приостановки аккаунта.
- Состояние сервисов, приватного хранилища, очередей писем и свежесть последнего успешного worker-цикла.

Интерфейс доступен на RU/KZ/EN. Содержимое пользовательских анкет, материалов и необработанный ответ сервера остаются на исходном языке. В браузере сохраняется только выбранный язык, а учётные данные сеанса остаются в HttpOnly cookie. Ошибки API не заменяются локальными примерами или успешными заглушками.

Приложение ещё не подтверждает публикацию в облаке, подключение почтового провайдера, юридическую готовность документов или выполнение процедур удаления. Эти состояния определяются фактической конфигурацией backend и работой оператора.
