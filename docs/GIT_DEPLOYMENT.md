# GitHub и публикация DanaConnect

Репозиторий: https://github.com/Alizhan2/Danaconnect.

Первоначальная ветка: `codex/initial-platform`. Она содержит сайт, отдельную админку, API, миграции, lockfiles, шаблоны конфигурации и инструкции оператору.

Состояние на 2 октября 2026 года: исходники опубликованы, GitHub Actions первоначального коммита завершился успешно. Автопубликация в Vercel ожидает подключения GitHub Login Connection в рабочем аккаунте владельца; текущий сайт опубликован отдельным CLI deployment.

## Настройки Vercel

- Используется существующий проект `danaconnect`; новый проект и новые базы для подключения Git не требуются.
- Корень проекта — корень репозитория. Framework preset — Services; маршрутизация трёх сервисов задана в `vercel.json`.
- Production branch должна совпадать с основной веткой репозитория. При первоначальном подключении это `codex/initial-platform`.
- Production environment variables хранятся в Vercel. `.env` и MFA enrollment не передаются через GitHub.
- Изменение production branch запускает сборку и публикацию через интеграцию Vercel с GitHub. Статус подключения и первой сборки фиксируется отдельно в `ACTIVATION_STATUS.md`.
- Preview-ветки не получают production credentials. Для работающего preview нужны отдельная база, отдельные ключи и другие изолированные ресурсы; копировать production configuration в Preview нельзя.
- Миграции схемы выполняются оператором отдельно, до публикации совместимого API. Git push не применяет Alembic автоматически.
- Расписание QStash сохраняет стабильный production URL и не требует повторного создания при каждом релизе.

## Работа над изменениями

Создать новую ветку `codex/<описание>`, сохранить изменения коммитом и открыть pull request. После просмотра изменений объединить в production branch. Изменения конфигурации провайдеров и обновления БД фиксировать в инструкции к релизу.

GitHub Actions при push и pull request компилирует API, проверяет TypeScript и собирает оба интерфейса. Существующие API-тесты запускаются только вручную через **Actions → Application checks → Run workflow → run_api_tests**. Автоматическая сборка не подтверждает пользовательские сценарии или доставку писем.

## Что исключено из репозитория

Закрытые `.env`, enrollment администратора, базы SQLite, резервные копии, приватные файлы участников, локальные снимки экранов, cloud state, установленное окружение и результаты сборки игнорируются. В репозитории разрешены только шаблоны `.env.example` и `.env.*.example`.

Не сохранять секреты в исходниках, документации, issue, PR или workflow logs. Перед отправкой просмотреть состав коммита; изменение `.gitignore` само по себе не удаляет уже опубликованные файлы из истории.
