# Состояние реализации DanaConnect

**Обновлено: 2 октября 2026 года, приложения опубликованы в облаке.** Документ разделяет наличие кода, выполненные наблюдения и подключение внешних сервисов. Публикация не является актом приёмки всех задач исходного backlog.

Платформа создана с нуля. Основные процессы реализованы; добавлены отдельная админ-панель и дополнительные модули. Сайт и админка опубликованы в Vercel на `danaconnect.vercel.app`; API сообщил DB ready. Создана новая Neon PostgreSQL, применены миграции до `0e82eab8e5ef` без учебного seed, создан настоящий администратор с зашифрованным MFA credential. Подключён private Blob, Gmail SMTP настроен, активировано расписание QStash каждые две минуты. Google credentials записаны в Production, Google Auth Platform пока Testing. Импорт authenticator владельцем ещё не подтверждён; функциональная приёмка входа/доставки/файлов не выполнялась. Демонстрационные записи и черновики документов не являются реальными участниками, результатами пилота или юридическим утверждением.

## Отдельная админ-панель

Приложение находится в `apps/admin`, имеет собственные зависимости/lockfile и порт **3001**. Пользовательский сайт остаётся в `apps/web` на **3000**; `/admin` сайта направляет в отдельное приложение.

Для облака админка собирается с `ADMIN_BASE_PATH=/admin`. Proxy направляет `/admin` и `/admin/*` к ней раньше остальных страниц, сохраняя префикс; API обслуживает `/api/v1`. Общий домен сохраняет cookie-сессию и Origin-проверки. В браузере сохраняется выбранный язык, а не credentials. Разделы работы с материалами/наградами, AI review и активностью вошли в подтверждённую сборку второй фазы. `/launch` и изменения третьей фазы также вошли в итоговую локальную сборку; функциональная приёмка не выполнена.

## Подготовка выпуска, фаза 4 — 2 октября

Подготовлены отдельный Vercel шаблон и генератор закрытых настроек, структурная проверка без сети и операторское обновление внешней PostgreSQL. Применение требует явного флага, точной ожидаемой версии; проверка и миграции используют одну транзакцию и переданное Alembic соединение. План не является чтением фактического состояния базы. Облачные команды генерации/валидации/применения не запускались в этой фазе.

API получает `VERCEL`/`DATABASE_POOL_MODE`, отключает локальный пул соединений в Vercel, запрещает неявный development и загрузки выше 3 MiB. Для PDF встроен DejaVu Sans 2.37 с исходной лицензией и контрольной суммой; таблица символов содержит RU/KZ/EN. Фактическая выдача нового PDF и облачная упаковка шрифта не проверялись. Конфигурация функции включает `assets/fonts/**`.

Добавлена сборка архива исходников с allowlist и SHA-256 манифестом. Подробный порядок: [RELEASE_PREPARATION.md](RELEASE_PREPARATION.md). Синтаксис Python/PowerShell рассматривается отдельно от функциональной приёмки; текущие frontend-сборки относятся к фазе 3, интерфейсы этой фазой не изменены. Vercel по-прежнему требует повторной авторизации; подключённых ресурсов и deployment URL нет.

## Наблюдение и диагностика, фаза 5 — 2 октября

Защищённый `/admin/operations` получает UTC время снимка, агрегаты очереди писем, возраст наступивших попыток, истёкшие сроки/leases, нормализованные группы отказов и подробности последнего цикла worker. Страница RU/KZ/EN допускает ручное обновление и скачивание ограниченного JSON без получателей и текста писем. Сигналы 15/5 минут являются операторскими индикаторами, не SLA; штатная отмена встречи/приглашения сама по себе не вызывает сигнал отказа почты. `sent` не подтверждает получение во входящих.

API генерирует UUID Request ID и фиксирует статус/время/шаблон маршрута в отдельном журнале. Неизвестные пути, параметры, IP, пользовательские данные и текст исключений в эту запись не попадают. Номер ошибки показан в общих компонентах сайта и админки. Uvicorn access log выключен в сценарии локального запуска и Docker; политики внешних журналов настраиваются отдельно. Миграции этой фазой не изменены.

Python compileall и PowerShell parser завершились без ошибок. Полные frontend-сборки прошли: web 22 записи маршрутов, admin 19, включая not-found; повторная сборка admin включает последние исправления подписей. API сообщил startup complete, оба standalone frontend — Ready; worker сообщил цикл с ненастроенной почтой. Приложения запущены через скрытые фоновые процессы, логи находятся в игнорируемом `artifacts/local-phase5`. Это старт процессов и компиляция, не функциональная приёмка страницы, экспорта или Request ID.

Порядок оператора: [MONITORING_RUNBOOK.md](MONITORING_RUNBOOK.md). Функциональная приёмка, внешние alerts, inbox/bounce, расходы, общие latency-метрики и production-провайдеры не подтверждены. Наличие диагностики не открывает пилот автоматически.

## Что остаётся до реального пилота

1. Владелец утверждает аудиторию, правила модерации/набора, тексты документов, переводы, обработку данных и права на бренд. Демонстрационные черновики заменить утверждёнными версиями.
2. Подключить аккаунт/домен, PostgreSQL, приватный S3, проверенную почту; создать production администратора с MFA. Google/AI подключаются только при выборе этих интеграций.
3. На выбранной инфраструктуре подтвердить миграции, права хранения, доставку OTP/приглашений/напоминаний, актуальность worker и доступ к закрытым материалам.
4. Согласовать и выполнить проверку новых сценариев, PostgreSQL concurrency, backup/restore, доступности и мобильных экранов; определить требования к нагрузке и мониторингу.
5. Установить эксплуатационные процедуры, владельцев поддержки и восстановления, правила ротации ключей, retention и purge. После этого открыть ограниченный пилот и фиксировать реальные результаты.

Не реализованы реальные платежи/донаты, автоматическое создание видеоконференций и двусторонняя синхронизация внешних календарей. Полное удаление пользовательских данных с очисткой обязательных записей, S3 версий и backups требует отдельной процедуры; интерфейс не имитирует завершение удаления. Single-host deployment не обеспечивает автоматический HA/failover или zero downtime.

## Операции разработки

`setup.ps1` устанавливает API, сайт и админку, сохраняет существующие `.env`, применяет миграции и отказывается работать с non-development конфигурацией. **Seed только с `setup.ps1 -Demo`**; `app.seed` запрещён вне development или без `DEMO_MODE=true`. Старт сервера не создаёт таблицы и демо-данные.

`dev.ps1` поддерживает `api`, `web`, `admin`, `worker`. SQLite остаётся средой разработки/testing. Production guards требуют PostgreSQL, свежие секреты, HTTPS origins/front URL и отключённые demo/debug/console; private files используют S3. Mail delivery и AI не заменяются успешными заглушками при отсутствии настройки.
