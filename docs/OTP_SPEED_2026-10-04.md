# Immediate sign-in email delivery

## Diagnosis

Production QStash schedule `danaconnect-production-jobs` is active with `*/2 * * * *`. Previously an ordinary sign-in request only persisted the challenge and encrypted email. The latest pre-change OTP waited 114.38 seconds until SMTP acceptance.

## Change

- Both ordinary sign-in and administrator-invitation OTP requests now attempt their own committed outbox item immediately, before completing the HTTP response.
- The existing processor accepts an optional outbox ID. The interactive request processes at most one item and cannot dispatch unrelated invitations or reminders.
- Provider calls run outside database transactions. The existing lease, expiry, retry backoff, attempt limit and stable Message-ID still apply.
- Transient provider failure or an existing worker lease returns `queued` for scheduled recovery. Permanent delivery failure returns a sanitized 503 rather than a success notice.
- Replacing an ordinary OTP retires the earlier challenge and cancels its unsent email, matching the existing invitation-code behavior.
- Public and admin screens distinguish immediate provider acceptance from queued recovery. Invitation expiry uses the remaining lifetime after the delivery attempt.
- Logs contain outcome and elapsed time, without codes, recipients, provider bodies or secrets.
- No migration, new provider, additional schedule or environment change was required.
